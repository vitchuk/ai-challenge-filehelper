# ai-challenge-filehelper

Десктопный AI-ассистент для работы с файлами проекта на вашем компьютере.

Вы даёте ассистенту доступ к одной папке, описываете цель словами — он сам находит нужные файлы,
читает и анализирует их, предлагает изменения в виде diff, применяет их после подтверждения и
ведёт журнал всех правок с возможностью отката.

---

## Возможности

- **Два провайдера моделей:** OpenCode Go (подписка) и DeepSeek. Настраиваются отдельно, ключи проверяются кнопкой «Проверить».
- **Работа только внутри выбранной папки.** Все операции с файлами проходят песочницу: абсолютные пути, выход через `..` и symlink-побеги отклоняются.
- **Ассистент сам инициирует работу с файлами** и определяет цель на уровне задачи, а не по прямой наводке. Он исследует проект инструментами, а не ждёт пути к файлу от вас.
- **Инструменты (tools):** `read`, `write`, `edit`, `glob`, `grep`, `list`.
- **Подтверждение правок с diff.** Каждая запись/правка показывается как diff (стиль `git diff` с номерами строк) и применяется только после «Применить». Есть режим «применять всё без подтверждения».
- **Журнал изменений** со снапшотами: для каждой правки доступны «Откатить» и «Применить» (переключение в обе стороны).
- **Автообновление дерева файлов** при изменении содержимого папки (в том числе извне).
- **Правила проекта через `AGENTS.md`.** Файл из корня рабочей папки подмешивается в системный промпт: конвенции, инварианты, ограничения.
- **Индикатор контекста** (кольцо) с подсказкой «использовано / максимум токенов» при наведении.
- **Ресайз панелей** по ширине с запоминанием пропорций между запусками.
- **Стриминг ответа** и сворачиваемые блоки «Размышления» / карточки вызовов инструментов.

## Как это работает

1. Вы выбираете папку проекта и формулируете цель.
2. Ассистент запускает агентный цикл: модель вызывает инструменты, чтобы найти и прочитать релевантные файлы.
3. Для `write`/`edit` он формирует предлагаемое изменение; интерфейс показывает diff и ждёт вашего решения.
4. Результат вызова возвращается модели, и цикл продолжается, пока задача не выполнена (с ограничением на число шагов).
5. Применённые правки попадают в журнал, где их можно откатить или применить заново.

Песочница путей проверяет каждый путь, который приходит от модели: путь разрешается относительно корня
рабочей папки и сверяется по реальному (symlink-разрешённому) расположению. Любой выход за пределы папки
приводит к ошибке инструмента.

## Архитектура

Приложение построено на Electron и разделено на три слоя:

- **main** — весь доступ к файловой системе, сеть и логика агента (окно и IPC, песочница, инструменты, агентный цикл, провайдеры, настройки, сессии, watcher папки);
- **preload** — типизированный мост `window.api` между интерфейсом и процессом;
- **renderer** — интерфейс на React.

Интерфейс не имеет прямого доступа к файловой системе и сети: все операции идут через IPC, ключи API
хранятся в main-процессе.

```
ai-challenge-filehelper/
├─ src/
│  ├─ main/
│  │  ├─ index.ts              окно и жизненный цикл приложения
│  │  ├─ ipc.ts               IPC-хендлеры, watcher папки, очередь подтверждений
│  │  ├─ sandbox.ts           валидация путей (песочница)
│  │  ├─ fsops.ts             применение изменений на диск
│  │  ├─ settings.ts          настройки и ключи (safeStorage)
│  │  ├─ sessions.ts          хранение сессий (JSON)
│  │  ├─ providers.ts         конфиги провайдеров и список моделей
│  │  ├─ openai-client.ts     стриминг chat/completions с tools
│  │  ├─ agent/
│  │  │  ├─ loop.ts           агентный цикл (инструменты, подтверждения, лимит шагов)
│  │  │  └─ prompt.ts         системный промпт и подмешивание AGENTS.md
│  │  └─ tools/               read, write, edit, glob, grep, list
│  ├─ preload/                типизированный мост window.api
│  ├─ renderer/               интерфейс на React
│  │  └─ src/
│  │     ├─ App.tsx
│  │     ├─ store.ts          состояние приложения (zustand)
│  │     └─ components/       чат, diff, журнал, дерево файлов, настройки
│  └─ shared/                 общие типы и контракт API
├─ tests/                     unit-тесты (vitest)
├─ electron.vite.config.ts
├─ electron-builder.yml
└─ package.json
```

## Требования

- Node.js 20 или новее
- npm 10 или новее
- Windows 10/11 (сборка и запуск проверены на Windows)

## Быстрый старт

```bash
npm install
npm run dev
```

`npm run dev` запускает приложение в режиме разработки с горячей перезагрузкой интерфейса.

Если после `npm install` Electron не запускается с сообщением о неудачной установке бинарника,
доустановите его вручную:

```bash
npm rebuild electron
```

## Сборка portable-приложения

```bash
npm run dist
```

Результат: `release\ai-challenge-filehelper.exe` — один переносимый файл без установки.

Примечания:

- Сборка не подписана, поэтому при первом запуске Windows SmartScreen может показать
  предупреждение «Неизвестный издатель» — выберите «Подробнее» → «Выполнить в любом случае».
- Перед повторной сборкой закройте запущенный экземпляр приложения, иначе сборщик не сможет
  перезаписать файлы в `release\win-unpacked`.

## Настройка провайдеров

Откройте «Настройки» в приложении и укажите ключи API:

| Провайдер   | Что нужно                                     |
| ----------- | --------------------------------------------- |
| OpenCode Go | API-ключ подписки (из консоли провайдера)     |
| DeepSeek    | API-ключ из платформы DeepSeek                |

Для каждого провайдера можно изменить Base URL (по умолчанию подставлен корректный адрес) и нажать
«Проверить» — приложение обратится к списку моделей и покажет статус. Список доступных моделей
подгружается динамически; для OpenCode Go показываются модели, обслуживаемые через
OpenAI-совместимый маршрут `chat/completions`.

Хранение данных:

- настройки и сессии — в каталоге приложения в `%APPDATA%\ai-challenge-filehelper`;
- ключи API шифруются средствами ОС (`safeStorage`), в файле на диске лежит только зашифрованное значение;
- сессии хранятся как отдельные JSON-файлы и удаляются из интерфейса (по одной или все сразу).

## Использование

1. Нажмите «Папка» и выберите папку проекта — ассистент получит доступ только к ней.
2. Опишите цель в поле ввода. Прямые пути к файлам указывать не нужно: ассистент найдёт их сам.
3. Когда он предложит изменение, изучите diff и нажмите «Применить» или «Отклонить».
4. Все применённые правки собраны в панели «Изменения»: их можно откатить или применить заново.
5. Чтобы задать правила и инварианты проекта, добавьте `AGENTS.md` в корень рабочей папки.

Примеры задач, которые решает ассистент:

- найти все места использования компонента, функции или API;
- обновить документацию (`*.md`) вслед за изменениями в коде;
- сгенерировать файл (README, ADR, changelog);
- проверить файлы на соответствие правилам и инвариантам и сообщить о нарушениях;
- подготовить список изменений и показать его в виде diff.

## Тесты

```bash
npm test
```

Покрыто unit-тестами:

- песочница путей (абсолютные пути, выход через `..`, symlink-побеги);
- инструмент `edit` (уникальное совпадение, отсутствие совпадения, неоднозначность, `replaceAll`);
- агентный цикл (обычный ответ, вызов инструмента, применение и отклонение правки, лимит шагов);
- генерация diff и классификация строк для отображения.

## Ограничения

- Для OpenCode Go доступны только модели, обслуживаемые через OpenAI-совместимый маршрут
  `chat/completions`. Модели, живущие на других маршрутах, в списке не показываются.
- Отсутствует инструмент запуска команд оболочки (по замыслу): ассистент работает только с файлами.
- На одну сессию — одна рабочая папка.
- Автоматическое сжатие истории диалога не выполняется: при переполнении контекста начните новую сессию.
